# 因子实验规模暴露诊断设计

**设计日期**：2026-08-21
**状态**：已确认执行（依据用户授权持续自主开发）
**适用范围**：`factor-composite-experiment` 的点时规模暴露审计

## 1. 背景与目标

稳健 Walk-forward 评估已经发现多数组合的 Ridge 权重高度集中。下一步需要回答：这些组合的收益或回撤是否同时来自规模暴露，而不只是因子本身。

本阶段先实现规模暴露诊断，不直接加入中性化约束。诊断应：

- 使用 `v_daily_valuation.market_cap` 的交易日点时值；
- 按每个信号日的可选股票池划分规模分位组；
- 比较全体可选股票与最终入选持仓在各规模组的占比和选择提升倍数；
- 输出逐信号日和跨期汇总，供后续决定规模中性化、规模约束或风险过滤；
- 明确当前 `stocks.industry` 只有未版本化的当前快照，暂不把它用于历史行业暴露结论。

## 2. 输入与点时边界

1. 候选配置必须使用已注册的 `factor-composite-experiment` 策略。
2. 因子输入由 `BacktestDataAccess` 加载，沿用因子自身的公告日 ASOF、行情历史窗口和上市天数过滤。
3. `market_cap` 由 `v_daily_valuation` 按信号日提供；缺失或非正市值的股票不进入规模分组，并记录覆盖率。
4. 规模分组只在同一信号日的可选股票池内计算，不能使用全历史固定分位点，否则会把市场规模结构变化混入暴露。
5. 每个信号日必须至少有 `quantile_count` 个有效市值候选；否则拒绝生成不完整的规模分组报告并返回清晰错误。
6. 行业标签当前存储在 SQLite `stocks.industry`，没有历史生效日期或版本；本阶段只输出“行业历史点时数据不可用”的限制，不读取该字段做历史统计。

## 3. 输出协议

输出目录默认位于 `workspace/factor_exposure_diagnostics/<name>_<timestamp>/`，包括：

| 文件 | 内容 |
|:---|:---|
| `parameters.json` | 回测配置、规模分组数、日期边界和行业数据限制 |
| `size_exposure.csv` | 每个信号日、每个规模组的可选数、入选数、占比和选择提升 |
| `size_exposure_summary.csv` | 跨信号日的规模组汇总、覆盖率和入选市值统计 |
| `size_exposure_coverage.csv` | 每个信号日可选池与入选持仓的市值覆盖率 |
| `summary.md` | 标准人读报告、规模暴露结论和行业数据限制 |

规模组编号从 1 到 `quantile_count`，1 表示当日较小市值组，`quantile_count` 表示当日较大市值组。`selection_lift = selected_share / universe_share`；分母为零时记为空，不用 0 伪造无暴露。

## 4. 报告内容

- 信号日数量、可选股票观测数、规模市值覆盖率和入选持仓数量；
- 各规模组平均可选占比、平均入选占比、平均选择提升倍数；
- 入选组合与可选池的市值中位数比较；
- 平均选择提升达到 1.25 或低于等于 0.75 的规模组强风险提示；这是审计阈值，不是显著性检验；
- 明确说明“规模暴露诊断不是因果归因，也不等同于行业中性”；
- 明确说明当前没有历史行业分类数据，不能据此判断历史行业集中度或实施历史行业中性化。

## 5. 非目标

- 不改变任何策略目标、权重、成交、回测收益或训练选择；
- 不用当前行业标签回填历史行业；
- 不在本阶段直接训练规模约束参数；
- 不把规模分组收益表解释为因子 alpha 证明。

## 6. 验收标准

- `market_cap` 通过统一估值视图加载，因子数据和规模分组均无未来日期读取；
- 纯计算测试覆盖等量分组、缺失市值、空持仓、零分母和多信号日汇总；
- CLI 输出五个固定产物（四个审计文件加一份报告），报告包含规模和行业限制章节；
- 旧策略与 `evaluate-factor-experiments` 行为不改变；
- Ruff、全量测试、真实点时规模诊断和 Review Gate 通过后提交。
