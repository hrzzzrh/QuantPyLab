## 1. 任务目标

现有系统已经具备面向 `factor-composite-experiment` 的训练、验证、测试、有限超参数搜索和 Walk-forward 流程。本计划补齐正式策略的训练能力，并在最近的财务公告日期、TTM、统一视图和回测数据访问修复之后重新生成可追溯的训练报告。

本计划的最终目标是：

1. 在不改变训练关闭时正式策略原有行为的前提下，让 `multi-factor-quality-value-momentum` 可以进入训练/验证/测试和 Walk-forward 评估。
2. 对正式策略的七个已注册因子，在训练窗口内使用点时因子和未来收益拟合权重；验证集只用于选择完整参数组合，测试集只运行入选组合。
3. 保留 `factor-composite-experiment` 现有研究路径，避免为了接入正式策略而改变既有实验结果。
4. 让训练缓存、回测缓存和 DuckDB 查询都具有明确的内存边界，避免扩大搜索空间后再次出现不可控的内存峰值。
5. 在标准报告中记录代码版本、因子版本、候选配置摘要和数据快照版本；若数据版本无法取得，评估应明确失败或降级为不可复现状态，不能继续伪装成完整审计结果。

### 2.1 正式策略当前七因子

第一版正式训练固定使用正式策略现有的七个因子，不在同一阶段自动搜索任意因子子集：

| 因子 | 当前默认权重 | 方向或类别 |
|:---|---:|:---|
| `price_momentum_120d` | 20.0% | 动量 |
| `price_trend_gap_120d` | 15.0% | 趋势 |
| `price_volatility_60d` | 10.0% | 低波动 |
| `valuation_pe_ttm` | 15.0% | 估值 |
| `valuation_pb` | 15.0% | 估值 |
| `quality_roe_weighted` | 12.5% | 质量 |
| `quality_operating_cashflow_ratio` | 12.5% | 质量 |

固定七因子集合是第一版的基线口径。因子集合选择、因子删减和结构候选属于后续独立研究问题，不能在正式策略接入时隐式加入，否则无法区分“权重学习”和“策略结构搜索”的效果。

## 3. 必须解决的技术缺口

### 3.1 正式策略训练适配

不能简单删除当前的策略名称检查。需要增加明确的训练适配层或策略能力协议，使训练器能够取得并写回以下信息：

- 训练因子名称及顺序；
- 因子专属参数和历史窗口；
- `holding_count`、上市日门槛和缩尾参数；
- 完整的训练权重映射；
- 将训练结果安全地应用到正式策略配置的方法。

正式策略的 `validate_parameters` 会把输入权重与默认权重合并。训练结果若只传递正权重而省略零权重因子，零权重因子可能被默认权重重新加回。因此正式策略适配必须明确支持“完整七因子权重覆盖”，包括显式的零权重，不能复用实验策略的部分权重写回逻辑而不验证。

实验策略最多允许六个因子，而正式策略包含七个因子。训练器的通用层不能依赖实验策略的六因子上限。

### 3.2 搜索口径

第一版正式策略训练采用以下边界：

- 因子集合固定为正式七因子；
- 因子窗口沿用正式策略当前声明，是否搜索窗口需单独配置，不能自动扩大；
- `holding_count`、缩尾范围和 `ridge_alpha` 可以沿用现有有限网格；
- `label_horizon_days`、`min_listing_days`、训练迭代上限和样本门槛继续作为固定研究口径，不参与同一轮收益优化；
- 训练权重是每个参数组合、每个训练窗口内重新拟合的内层模型参数；
- 测试集不参与权重拟合、参数选择或失败组合恢复。

如果后续要比较不同因子集合，必须在研究配置中显式列出候选策略或候选因子集合，并记录每个候选的因子版本和搜索覆盖；不做无上限的自动子集穷举。

### 3.3 数据版本与点时口径

训练必须基于当前已经修复的财务数据和点时查询规则，重点复核：

- 四张财务表和东财指标表的公告日期修复结果；
- `fin_ttm` 使用统一后的报告期公告日期；
- `report_date >= max(上市日期, 2010-01-01)` 的数据边界；
- TTM 不使用数据可用日期字段，且标签、因子和回测信号不能穿越；
- 估值、指标和行情重复键仍按确定性规则去重；
- 训练报告记录当前代码提交、候选配置哈希、因子版本和数据快照标识。

### 3.4 内存与资源边界

训练和回测输入缓存均已按 split 使用有界 LRU，行情读取和滚动因子计算也按股票批次执行：

- 训练数据缓存只在当前 split 内有效；
- 使用明确的最大条目数淘汰；正式配置的训练缓存最多保留 2 组，评估器最多保留 2 组因子输入和 1 个市场区间；
- split 结束后显式清空引用并执行必要的资源释放；
- 不缓存每个试验的完整回测结果和测试集结果；
- 保留 DuckDB 256MB、2 线程的查询资源限制；
- 真实评估使用独立进程或等价方式记录峰值 RSS，报告中记录是否超过 2 GiB 进程资源预算；
- 若搜索空间扩展导致内存超限，优先减少并发和缓存，不降低研究有效性门槛；本次全量验证峰值约 2.73 GB，已在报告中标记超预算，不能宣称资源门禁通过，但按用户要求以运行正确为优先保留结果。

## 5. 验收标准

### 5.1 功能正确性

- 训练关闭时，正式 `multi-factor-quality-value-momentum` 的配置、目标、成交、净值和报告口径与改造前一致。
- 训练开启时，正式策略可在训练窗口内拟合完整七因子权重，并能在验证和测试阶段冻结使用。
- 权重非负、有限、总和为 1；零权重因子不会被默认权重意外恢复。
- 每个 Walk-forward 窗口独立训练和选择，不继承前一窗口权重。
- 测试阶段只运行验证集入选组合，测试数据不参与选择。
- 因子、财务数据和标签严格遵守点时和 T+1 规则。

### 5.2 数据和可复现性

- 报告记录代码提交、候选配置 SHA256、因子版本和数据快照版本。
- 报告记录训练/验证/测试信号日数、观测数、门槛、失败组合和权重集中度。
- 当前数据修复后的结果与旧报告明确分开，不覆盖旧产物、不混合比较。
- 真实评估能够重复生成相同的目标、成交、净值和审计 CSV；生成时间等非确定字段除外。

### 5.3 内存和工程质量

- 训练缓存有明确上限，且不同 split 之间不保留训练宽表。
- 真实烟测和稳健评估记录峰值内存；本次全量评估峰值超过 2 GiB，报告已明确标记，不能把资源控制说成通过。按用户要求不为降低内存牺牲运行正确性，也不降低研究有效性门槛。
- 核心代码变更补充 mock 网络/数据库的测试。
- 按项目门禁依次通过 `uv run ruff check .`、`uv run ruff format --check .` 和 `uv run pytest tests/`。
- 只有开发、测试、Lint 和临近提交的 Review Gate 全部通过后，才能提交代码。

## 6. 研究边界与暂不自动化事项

- 不根据一次 Walk-forward 的测试结果自动修改正式策略配置。
- 不把测试结果用于调整因子权重、候选集合、持仓数量或搜索范围。
- 不在正式策略接入时同时引入任意因子子集穷举、标签期限搜索和上市日门槛搜索。
- 不把训练得到的权重直接视为因子长期有效性的证明；仍需结合权重稳定性、边际贡献、行业/规模暴露、容量和成本结果判断。
- 不因为内存压力而取消点时门禁、缩短有效性门槛或读取测试集进行中途调参。
