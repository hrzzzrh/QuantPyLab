# 历史行业覆盖率与点时行业暴露诊断设计

**设计日期**：2026-08-21
**状态**：已完成
**适用范围**：因子实验候选池/入选持仓的申万历史行业覆盖率和选择暴露；不实施行业中性化

## 1. 目标与边界

历史行业数据资产已经具备，但在接入行业约束前，必须先回答两个问题：

1. 每个历史信号日的候选池和入选持仓，有多少股票能够按 `effective_date` 找到行业分类；
2. 在已分类样本中，策略是否相对候选池偏向或回避某些申万行业代码。

本阶段只做审计，不改变因子值、候选池、目标权重、成交、训练或回测结果；不使用当前 `stocks.industry` 回填缺失，不做行业中性化，不把 `source_updated_date` 当作可见日期。

## 2. 点时口径

候选池和目标持仓沿用 `factor-composite-experiment` 的现有生成逻辑。行业通过统一视图 `industry_classification_sw` 做 ASOF：

```sql
ASOF LEFT JOIN industry_classification_sw AS industry
  ON points.symbol = industry.symbol
 AND points.date >= industry.effective_date
```

同一股票同一信号日只保留最近的行业生效记录；信号日早于首条分类记录时保持缺失。缺失行业仍计入候选数/持仓数，但不进入行业占比和选择提升分母，并单独计入覆盖率。

行业代码保持六位字符串。由于当前源资产未提供稳定的行业名称映射，本阶段报告按申万行业代码输出，不猜测名称或跨标准拼接名称。

## 3. 报告产物

新增 `diagnose-factor-industry-exposures` 命令，输入与规模诊断相同的因子实验回测配置，输出到 `workspace/factor_industry_exposure_diagnostics/`：

- `industry_exposure.csv`：逐信号日、逐行业代码的候选数、入选数、占比和选择提升；
- `industry_exposure_summary.csv`：跨信号日的行业代码汇总；
- `industry_exposure_coverage.csv`：逐信号日候选池和入选持仓的行业覆盖率；
- `parameters.json`：配置、ASOF 字段和数据资产信息；
- `summary.md`：信号日、覆盖率、行业暴露和限制说明。

选择提升定义为“入选持仓行业占比 / 已分类候选池行业占比”。没有有效分类的股票不伪造为某个行业，也不进入行业分组汇总。

真实验收结果：反转和价值/成长两套配置均为 104 个信号日。两套配置候选池行业覆盖率均值 99.7%、最低 99.1%；反转入选持仓覆盖率均值 100.0%、最低 95.0%，价值/成长均值 99.7%、最低 95.0%。反转组合最大平均占比差为申万代码 `430101` 的 +6.8 个百分点；价值/成长组合为 `430101` 的 +20.6 个百分点。两份报告均提示少量行业代码累计候选数低于 100，选择提升比率需结合绝对候选数和占比差解释。

## 4. 验收标准

- 点时行业加载必须通过统一视图和 ASOF，不直接扫描 Parquet，不使用当前行业快照回填；
- 纯函数测试覆盖精确生效日、首条记录之前、行业切换、缺失覆盖率、目标不属于候选池和重复输入；
- CLI 测试覆盖配置校验和报告文件写入；
- 使用反转、价值/成长两套真实配置运行覆盖率审计，记录信号日数量、候选/持仓覆盖率、缺失数量和主要行业选择提升；
- Ruff 检查、格式检查和全量 561 项测试已通过；提交前 Review Gate 已通过，待提交；
- 诊断结果只写研究报告，不改变现有策略行为。
