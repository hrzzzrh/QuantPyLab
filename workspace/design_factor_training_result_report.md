# 因子训练标准结果报告设计

**设计日期**：2026-08-20
**设计状态**：已完成实施
**适用范围**：`evaluate-factor-experiments` 的训练、验证、测试和 Walk-forward 输出

## 1. 目标

当前评估器已经输出 `training_models.csv`、`hyperparameter_trials.csv`、`candidate_metrics.csv`、`selections.csv`、`evaluation_failures.csv` 和一个简短的 `summary.md`。这些文件适合机器审计，但不能直接回答一次训练最重要的研究问题：

1. 这次训练实际使用了什么数据、什么时间窗口和什么标签。
2. 一共训练了多少个候选组合，多少成功，多少失败，失败原因是什么。
3. 每个窗口最终选择了什么因子组合、什么超参数和什么拟合权重。
4. 训练集、验证集和测试集的表现分别如何，测试结果是否只来自入选组合。
5. 权重是否高度集中、时间样本是否太少、训练表现是否明显好于验证表现。
6. 这次结果能支持什么结论，不能支持什么结论，下一步应该检查什么。

本方案把 `summary.md` 升级为固定结构的标准人读结果报告。文件名保持不变，避免破坏现有输出路径和下游脚本；CSV 文件继续作为完整明细和机器读取接口。

## 2. 输出协议

每次 `evaluate-factor-experiments` 成功完成后，结果目录必须包含以下文件：

| 文件 | 定位 | 是否作为报告正文依据 |
|:---|:---|:---:|
| `summary.md` | 标准人读结果报告，按固定章节输出 | 是 |
| `parameters.json` | 研究配置、切分、训练参数、搜索空间和复现审计快照 | 是 |
| `training_models.csv` | 每个窗口、每个组合的训练状态和拟合权重 | 是 |
| `hyperparameter_trials.csv` | 每个搜索组合的参数、拟合权重、训练/验证指标和失败原因 | 是 |
| `candidate_metrics.csv` | 全部训练/验证指标，以及入选组合的测试指标 | 是 |
| `selections.csv` | 每个窗口的验证选择和测试结果 | 是 |
| `evaluation_failures.csv` | 训练、验证、测试回测或指标计算失败的组合与原因 | 是 |
| `research_validity.csv` | 训练、验证、测试阶段的样本覆盖门禁明细 | 是 |
| `selection_diagnostics.csv` | 每个窗口的验证比较规模、样本规模、排名差距和选择负担风险 | 是 |

`summary.md` 是面向研究人员的结论入口，不复制全部 CSV 明细。报告中的数字必须能在上述 CSV 中定位；如果报告只展示 Top-N 组合，必须明确说明完整结果仍在 `hyperparameter_trials.csv`。

## 3. 报告固定结构

报告章节顺序固定，不因是否启用超参数搜索或 Walk-forward 而改变；没有数据的章节显示“本次未启用”，不能静默省略。

### 3.1 报告身份与执行状态

报告开头输出：

- 研究名称和报告生成时间。
- 研究配置路径和候选配置路径。
- 报告状态：`completed`、`completed_with_exclusions` 或 `failed`。
- 固定切分和 Walk-forward 是否启用。
- 选择指标及方向，例如 `sharpe_ratio (max)`。
- 代码和数据版本信息；如果当前运行环境无法取得 Git 提交号，明确写入“未取得”，不能伪造版本。

状态口径：

- `completed`：每个窗口都有有效训练、验证选择和测试结果，且没有失败组合。
- `completed_with_exclusions`：每个窗口都有有效选择和测试结果，但存在训练失败或被排除的组合。
- `failed`：至少一个窗口没有可用组合，无法完成验证选择或测试；当前评估器可以抛出错误，但报告接口必须保留明确失败原因。

### 3.2 研究配置与时间边界

报告用表格完整列出：

| 项目 | 内容 |
|:---|:---|
| 候选因子组合 | 候选 ID、对应 TOML 路径、因子名称 |
| 信号频率 | 月末信号；信号日收盘后生成，下一交易日开盘成交 |
| 标签 | 从信号日后下一交易日开盘，到 `label_horizon_days` 个交易观察后的收盘收益 |
| 固定训练/验证/测试 | 每段开始日、结束日和交易日数量 |
| Walk-forward | 窗口数量、训练/验证/测试年数和步长 |
| 固定训练参数 | `label_horizon_days`、`min_listing_days`、样本门槛、最大迭代次数 |
| 外层搜索 | 是否启用、组合上限和实际展开组合数 |
| 选择规则 | 指标、方向、并列时的稳定排序规则 |

报告必须特别显示“信号日数量”，不能只显示股票观测行数。股票观测行数是“信号日 × 当日有效股票”的横截面样本，不能代替时间维度样本。

### 3.3 点时数据与样本覆盖

每个训练窗口至少输出：

- 训练信号日数量、最早信号日和最晚信号日。
- 每个成功组合的 `observation_count` 和 `signal_date_count`。
- 因子窗口所需的历史行情是否满足。
- 训练标签是否需要读取训练结束日之后的行情；这些行情只能出现在标签计算说明中，不能计入训练回测收益。
- 是否发生训练数据不足、因子全缺失、标签无效或权重退化。
- 验证和测试实际生成的目标观测数、信号日数量，以及与 `[validity]` 门槛的比较结果。

报告使用以下固定提示：

- 训练 `signal_date_count < 24`：研究有效性门禁失败，不能进入验证选择。
- 验证或测试实际可执行 `signal_date_count < 11`，或目标观测数低于对应 `[validity]` 门槛：研究有效性门禁失败，不能把该阶段结果作为可靠结论。
- 已通过门禁但信号日数量少于 12 时，仍可输出“时间样本较少，权重稳定性需要谨慎解释”的研究提示。
- `max(factor_weight) >= 0.90`：提示“拟合权重高度集中”，应检查是否退化为单因子模型。
- 训练区间只有少数月份时，必须在结论中明确写出实际信号日数量。

### 3.4 搜索与训练状态

启用外层搜索时，报告先给出总览：

| 指标 | 数值 |
|:---|---:|
| 候选组合数量 | — |
| 展开参数组合数量 | — |
| 成功拟合数量 | — |
| 失败数量 | — |
| 成功率 | — |
| 失败原因种类数 | — |

随后按窗口和候选汇总成功/失败数量，并按失败原因分组。失败原因必须使用训练器实际抛出的错误文本，不将“权重全部退化为零”“训练样本不足”等原因合并为模糊的“训练失败”。

报告展示每个窗口验证集得分最高的 Top 10 组合，字段至少包括：

- 候选 ID和试验 ID。
- 因子组合及因子窗口参数。
- `holding_count`、缩尾范围和 `ridge_alpha`。
- 训练状态、训练集选择指标和验证集选择指标。
- 是否为最终入选组合。

组合总数超过 10 时，报告必须标明“仅展示 Top 10，完整组合见 `hyperparameter_trials.csv`”。未启用搜索时，本节仍输出候选数量和训练状态，但不伪造网格搜索结果。

### 3.5 验证集选择稳健性

每个固定或 Walk-forward 窗口输出一行 `selection_diagnostics.csv`，至少包括比较组合数、候选数、验证信号日和观测数、入选分数、第二名分数、第一/二名差距、并列第一数量、分数分布和组合/信号日比例。验证信号日少于 12 个，或比较组合数多于验证信号日时，报告必须明确提示时间样本不足或多重比较负担。该诊断不改变选择指标和测试集隔离，也不把警告伪装成硬门禁。

### 3.6 入选模型与拟合权重

每个固定切分或 Walk-forward 窗口输出一行入选模型：

| 窗口 | 候选 | 试验 | 因子参数 | 持仓数 | 缩尾范围 | Ridge | 权重 |
|:---|:---|:---|:---|---:|:---|---:|:---|

权重必须从该窗口训练结果中读取，不能读取候选 TOML 的原始权重。权重表同时显示：

- 权重和是否为 1。
- 非零因子数量。
- 最大权重和对应因子。
- 是否触发权重集中提示。

Walk-forward 启用时，额外输出各因子跨窗口的权重均值、标准差、最小值、最大值和非零窗口数，用于区分“某一窗口偶然选中”和“长期稳定使用”。

### 3.7 训练、验证和测试表现

每个窗口输出入选组合的三段指标：

| 阶段 | 总收益 | 年化收益 | 年化波动 | 夏普 | 最大回撤 | 交易日数 |
|:---|---:|---:|---:|---:|---:|---:|
| train | — | — | — | — | — | — |
| validation | — | — | — | — | — | — |
| test | — | — | — | — | — | — |

规则如下：

- 训练集和验证集指标来自该试验自己的冻结权重。
- 测试集只显示验证集入选试验的结果；未入选组合不读取测试区间。
- 报告必须明确验证集用于选择，因此验证指标不是最终无偏表现。
- 固定切分与 Walk-forward 结果分开，不把两者混成一条收益曲线。
- Walk-forward 汇总只针对测试段，至少给出窗口数、测试总收益均值/中位数、正收益窗口比例、夏普均值/中位数和最差最大回撤；没有每日净值时不伪造复合收益曲线。

### 3.8 稳定性与风险提示

报告不自动把“验证集最高”表述为“有效因子”，而是固定输出以下事实检查：

1. 训练信号日是否过少。
2. 拟合权重是否高度集中。
3. 训练指标是否明显优于验证指标。
4. 不同 `ridge_alpha` 是否产生相同权重和相同指标。
5. 因子窗口改变是否导致组合全部失败。
6. 各 Walk-forward 窗口的入选候选和权重是否频繁切换。
7. 测试段是否存在极端回撤或测试窗口数量过少。
8. 验证集比较组合数是否超过有效信号日数，是否存在并列第一或验证时间样本偏少。

每项使用“事实 + 处理结果”的格式，例如“训练信号日为 6 个，低于 24 个硬门槛；该组合已被阻断，不能进入验证选择”。报告不得只输出“模型好/模型坏”这类没有口径的结论。

### 3.9 研究结论与下一步

结论固定分为三段：

- **本次完成了什么**：候选数量、成功/失败数量、选择规则和测试是否完成。
- **本次观察到什么**：入选组合、权重集中度、训练/验证/测试表现和 Walk-forward 稳定性。
- **本次不能证明什么**：明确说明样本时间长度、验证选择偏差、测试窗口数量和未覆盖的市场阶段。

最后给出下一步检查清单，优先包括：扩大训练时间范围、增加有效信号日、检查失败因子窗口、重新做因子诊断、检查权重稳定性和独立测试集验证。报告不直接给出“买入/实盘启用”结论。

## 4. 现有文件与报告章节的对应关系

| 报告内容 | 主要数据来源 |
|:---|:---|
| 报告身份、配置和时间边界 | `parameters.json`、评估配置对象 |
| 训练信号日、训练样本和权重 | `training_models.csv` |
| 参数组合、失败原因、训练/验证指标 | `hyperparameter_trials.csv` |
| 全部候选阶段指标 | `candidate_metrics.csv` |
| 入选组合和测试结果 | `selections.csv` |
| 研究有效性门禁实际值和失败原因 | `research_validity.csv` |
| 验证集选择比较规模和多重比较风险 | `selection_diagnostics.csv` |
| 稳定性提示 | 上述文件聚合计算，不新增未经来源支持的指标 |

报告不得把测试结果写入候选配置，也不得用测试指标重新排序或改变入选模型。

## 5. 验收标准

- `summary.md` 按本方案固定输出全部章节；固定切分、Walk-forward、启用搜索和关闭搜索四种模式都能生成结构完整的报告。
- 报告能正确区分股票观测数和月末信号日数，并在样本覆盖不足时阻断对应阶段并给出实际值、门槛和原因。
- 报告能展示成功/失败组合、失败原因、入选参数和训练权重。
- 报告中的测试指标只来自入选组合；测试结果不参与验证选择。
- Walk-forward 报告能分别展示各窗口并给出不伪造复合净值的测试段汇总。
- 单元测试覆盖无搜索、有限搜索、训练失败、权重集中、信号日不足和 Walk-forward 汇总。
- 使用真实点时数据完成一次报告烟测，报告正文与 CSV 结果一致。
- 更新 `docs/backtest.md`、`docs/factor_library.md` 和 `docs/usage.md` 的输出协议说明。
- Ruff、全量测试和真实烟测全部通过；本设计已完成实施。
