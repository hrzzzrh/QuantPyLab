# 因子库后续开发计划

**计划日期**：2026-08-19
**计划状态**：持续执行（依据用户授权自主推进，复杂功能仍按设计文档记录确认锁）
**适用范围**：日频股票横截面因子、因子诊断和多因子回测

## 1. 计划定位

`analysis/factors/` 首期已经建立了独立因子定义、注册、批量计算、截面变换和点时数据访问能力，并完成了两个既有策略的因子化迁移。后续工作的重点不是简单增加因子数量，而是建立一套可以解释、验证和迭代的因子研发流程。

本计划遵循以下分层：

- 因子只描述某个时点股票的单一特征，输出 `date`、`symbol`、`value`。
- 因子库负责公式、输入需求、历史窗口、方向和版本。
- 截面排名、缩尾、标准化、行业或规模中性化由通用变换或策略明确处理。
- 策略负责组合因子、筛选标的、风险约束和目标权重。
- 回测引擎负责成交、成本、复权收益和退市清算。

计划文档放在 `workspace/`，因为它描述的是未来开发路线和候选方案，不是系统当前状态。已稳定实施的因子口径、数据依赖和无未来函数规则，完成后同步维护到 `docs/factor_library.md` 及相应数据目录文档。

## 2. 当前基线

当前因子库已经包含：

| 类别 | 已有因子 |
|:---|:---|
| 成长 | `growth_revenue_yoy`、`growth_deduct_profit_yoy` |
| 动量与趋势 | `price_momentum_120d`、`price_reversal_20d`、`price_trend_gap_120d`、`price_trend_above_ma_120d` |
| 波动 | `price_volatility_60d` |
| 估值 | `valuation_pe_ttm`、`valuation_pb`、`valuation_ps_ttm`、`valuation_pcf_ttm` |
| 财务质量 | `quality_roe_weighted`、`quality_operating_cashflow_ratio`、`quality_roic` |

估值因子通过 `v_daily_valuation` 使用 `fin_ttm.pub_date` 进行点时对齐；财务指标因子通过 `fin_indicator.数据可用日期` 进行点时对齐；行情因子只能使用当前交易日及之前的行情。

## 4. 研发优先级

### 4.1 第一批：补齐已有数据资产中的高价值因子

第一批优先选择当前数据表和统一视图已经具备、实现成本低、与现有因子有明确互补性的因子。

| 因子名 | 类别 | 数据与口径 | 方向 | 优先级理由 |
|:---|:---|:---|:---|:---|
| `valuation_ps_ttm` | 估值 | `v_daily_valuation.ps_ttm`，只保留正值 | 越低越好 | 覆盖亏损但有收入的公司 |
| `valuation_pcf_ttm` | 估值 | `v_daily_valuation.pcf_ttm`，只保留正值 | 越低越好 | 补充 PE 对现金流的忽略 |
| `growth_revenue_yoy` | 成长 | `fin_indicator.营业总收入同比增长` | 越高越好 | 衡量业务扩张速度 |
| `growth_deduct_profit_yoy` | 成长 | `fin_indicator.扣非净利润同比增长` | 越高越好 | 比归母净利润增长更少受一次性损益影响 |
| `quality_roic` | 质量 | `fin_indicator.投入资本回报率` | 越高越好 | 比单独 ROE 更接近经营资本效率 |
| `price_reversal_20d` | 行情 | `close_hfq / close_hfq.shift(20) - 1` 的反向信号 | 越高越好 | 与 120 日动量形成互补 |

第一批不把 PE 的倒数另做成 `earnings_yield`，也不同时增加大量不同窗口的动量因子，避免产生公式重复和高度相关的表面扩展。

### 4.2 第二批：稳健性和风险因子

第一批经过因子诊断后，再开发以下因子：

| 因子名 | 类别 | 数据与口径 | 备注 |
|:---|:---|:---|:---|
| `quality_roe_deducted` | 质量 | `fin_indicator.净资产收益率_扣非/加权` | 与加权 ROE 比较增量信息 |
| `quality_sales_cashflow_ratio` | 质量 | `fin_indicator.销售现金流/营业收入` | 观察收入现金实现质量 |
| `quality_gross_margin` | 质量 | `fin_indicator.毛利率` | 需要检查行业差异和稳定性 |
| `risk_leverage` | 风险 | `fin_indicator.资产负债率` 的反向排序口径 | 金融行业需单独处理 |
| `risk_interest_coverage` | 风险 | `fin_indicator.利息保障倍数` | 负值和缺失值必须明确处理 |
| `price_max_drawdown_120d` | 风险 | 120 个交易日滚动最大回撤 | 适合作为风险约束或低风险评分 |
| `market_liquidity_20d` | 交易性 | 20 日成交额或成交额/市值滚动均值 | 更适合作为可交易性过滤条件 |

资产负债率、PB、ROE 和 ROIC 具有明显行业属性。行业中性化或行业内排名应在通用截面变换和策略接入阶段解决，不能在单个因子内部偷偷改变原始口径。

## 5. 因子诊断能力

在持续增加因子之前，先建立最小可用的因子诊断流程。每个候选因子至少需要输出：

- 每个交易日的覆盖率和有效股票数量。
- 截面 Rank IC、IC 均值、IC 标准差和 IC 信息比率。
- 分位数组合收益及多空分位差，检查收益是否单调。
- 因子换手率、信号自相关和持有期衰减。
- 与现有因子的截面相关性和时间序列相关性。
- 分市场阶段、行业和市值分组后的稳定性。
- 极端值、负值、缺失值和数据可用日期分布。

诊断必须使用下一交易日可成交收益，不能使用信号生成日收盘价之后不可获得的信息。因子诊断结果用于决定因子是否进入策略，不以单段回测收益作为唯一通过标准。

## 6. 点时数据与数据质量要求

### 6.1 财务因子

- 估值因子只使用 `v_daily_valuation` 输出，并继承 `fin_ttm.pub_date` 的 ASOF 规则。
- `fin_ttm.pub_date` 使用当前报告期四源统一后的公告日期；上年年末和上年同期只参与 TTM 数值计算，不能把历史日期传播给当前 TTM。
- 非 TTM 财务指标使用 `数据可用日期`，确保四个财务来源均已可用。
- 不按报告期截止日直接连接交易日，不使用更新日期替代披露可用日期。
- 对同比增长、比率和倍数类字段核对报告类型、分母为零、负分母和异常极值。

### 6.2 行情因子

- 滚动窗口只使用当前日期及之前的行情。
- 复权价格因子统一使用系统的 `close_hfq`。
- 窗口不足时返回缺失，不用首个可用值填充。
- 成交额类因子须保留单位和币种转换说明，并区分 alpha 因子与交易可执行性过滤条件。

### 6.3 因子结果契约

每个新因子必须声明：

- 稳定且唯一的名称。
- 公式、经济含义和高低值方向。
- 输入字段及其数据源。
- 最大历史窗口。
- 点时日期口径。
- 缺失值、非正值、极端值和分母异常处理。
- 因子版本和变更原因。

## 7. 分阶段实施

### 阶段零：诊断基础设施

1. 固定因子诊断输入和收益计算口径。
2. 增加单因子分组收益、Rank IC、覆盖率和相关性报告。
3. 增加行业、规模和流动性分组分析。
4. 增加因子结果快照与参数记录，但暂不把因子结果物化为长期数据表。

### 阶段一：第一批六个因子

1. 扩展估值视图和数据访问字段选择。
2. 实现两个估值、两个成长、一个质量和一个短期反转因子。
3. 为每个因子增加手算样例、ASOF 对齐和未来数据隔离测试。
4. 在现有多因子策略之外增加实验配置，先进行单因子和小组合回测。

### 阶段二：风险与中性化

1. 根据诊断结果决定是否纳入扣非 ROE、销售现金流、毛利率和杠杆因子。
2. 增加行业内排名、规模中性化或行业哑变量中性化能力。
3. 将最大回撤和流动性因子优先用于风险约束、股票池过滤，再评估其 alpha 价值。

### 阶段三：策略组合验证

1. 比较价值、成长、质量、动量和风险因子单独及组合后的边际贡献。
2. 进行等权、风险调整权重和行业约束的对照回测。
3. 检查换手、交易成本、容量、缺失覆盖率和不同上市阶段的表现。
4. 对表现稳定的组合更新策略配置和 `docs/backtest.md`。

### 阶段四：高级因子评估

只有基础因子和诊断体系稳定后，才考虑：

- 行业中性残差动量。
- 盈利质量变化或因子趋势，而不是只使用单期水平。
- 基于公告日期的业绩公告后漂移。
- 需要外部预期数据的盈利预期修正。

事件类和预期类因子需要新的可靠数据源及版本化历史数据，不能直接用当前指标表的更新字段替代。

## 8. 测试与验收门禁

每个新增因子必须至少覆盖：

1. 公式手算样例。
2. 正常输入、缺失输入、非数值输入和异常分母。
3. 结果唯一性和输出字段契约。
4. 财务因子的 ASOF 日期边界。
5. 修改未来日期数据不影响过去因子值。
6. 截面排名、方向和缺失处理。
7. 与数据访问层的集成测试。

涉及核心代码时，完成开发后必须通过：

```bash
uv run ruff check .
uv run ruff format --check .
uv run pytest tests/
```

如果新因子接入策略，还必须验证旧策略行为不变，并运行至少一次真实点时数据的端到端回测烟测。

## 9. 暂不纳入范围

- 机器学习自动选因子和参数寻优。
- 依赖分析师一致预期但当前系统未保存历史版本的数据。
- 盘中、分钟级和高频微观结构因子。
- 未完成点时版本化前的财务重述因子。
- 为尚未证明有稳定价值的因子建立长期物化数据表。

## 10. 计划完成标准

本计划完成不以“注册了多少个因子”为标准，而以以下结果为准：

- 因子均有明确的经济含义、数据口径和版本记录。
- 因子计算不产生未来函数，财务日期规则可追溯。
- 因子诊断能够识别覆盖率、相关性、换手和稳定性问题。
- 策略能解释每个因子的使用方式和边际贡献。
- 新增因子不改变既有策略已验证的行为。
- 代码、测试、数据目录文档和回测文档保持一致。

任何一批具体因子进入实现前，应根据本计划另行提交范围明确的开发提案并获得确认。
