# 多因子组合边际贡献验证设计

## 1. 背景

当前正式策略 `multi-factor-quality-value-momentum` 使用七个因子和固定权重。训练、暴露和选股约束研究已经可以比较整体收益与风险，但还不能回答：组合表现是否来自多个因子的互补，还是几乎由某一个因子决定。需要在固定测试区间内运行单因子、完整组合和 leave-one-out 组合，审计每个因子被加入或移除后的收益、回撤、换手、成本和目标变化。

本功能是研究诊断，不改变正式策略配置、因子权重、训练结果或回测默认行为。

## 2. 目标与非目标

### 2.1 目标

1. 读取现有 `multi-factor-quality-value-momentum` TOML 和七个因子的正式权重。
2. 在七个因子都有效的共同点时候选池上生成 15 个变体：
   - `full_combination`：正式七因子权重；
   - `single_<factor>`：每次只保留一个因子，单因子权重为 1；
   - `leave_one_out_<factor>`：移除一个因子，剩余因子按正式相对权重重新归一化。
3. 在相同的 T+1 开盘、后复权、手续费、滑点、退市清算和基准口径下运行全部变体。
4. 输出每个因子的组合边际结果、与完整组合的目标重合、逐日净值、逐笔成交和成本审计。

### 2.2 非目标

- 不根据测试结果重新拟合或调整正式权重。
- 不让单因子变体使用其独有的缺失数据股票，从而把覆盖变化混入边际贡献。
- 不进行新的超参数搜索、组合优化或因果归因。
- 不把测试区间结果自动接入正式策略。

## 3. 设计

### 3.1 共同候选池和权重口径

先按正式策略的点时数据需求加载七个因子，再只保留七个因子同时有效、满足上市交易日门槛且处于月末信号日的股票。所有 15 个变体都使用该共同候选池、同一信号日集合和同一 `holding_count`。

权重协议如下：

| 变体 | 权重 |
|:---|:---|
| `full_combination` | 使用配置中的正式归一化权重 |
| `single_<factor>` | 该因子权重为 1 |
| `leave_one_out_<factor>` | 删除该因子后，将剩余正式权重除以剩余权重总和 |

每个变体仍按现有因子元数据统一方向，先按信号日缩尾和百分位排名，再按变体权重合成分数，前 `holding_count` 只等权持有。因子加入/移除造成的目标变化通过与 `full_combination` 的逐信号日目标重合审计。

### 3.2 统一成交和成本

所有目标使用同一份 `PreparedMarketData` 和 `DailyBacktestEngine`：

- 信号日收盘生成目标，下一实际交易日开盘执行；
- 使用同一行情日历、后复权开收盘、初始资金、手续费、滑点和基准；
- 复用引擎现有停牌阻塞、退市清算和现金处理；
- 换手只统计 BUY/SELL 的单边名义金额，DELIST 和 SKIP_REBALANCE 单独计数。

评估区间支持命令行显式覆盖。只有调用方提供预先锁定、未参与权重或方案选择的测试日期，报告才标记为锁定样本外比较；省略时使用 TOML 原始区间并明确标记边界。

### 3.3 可复现性约束

研究输入依赖的 `daily_kline` 统一视图按 `(symbol, date)` 确定性去重；估值视图和指标查询的 ASOF 右表按股票及生效日期排序。日频回测执行计划和调仓成交也按股票代码排序，避免 Python 集合遍历顺序改变交易记录、成本汇总或报告末位结果。锁定区间验收除检查 15 个变体和 24 个信号日外，还需至少独立运行两次并逐文件比较目标、净值、成交、覆盖和重合审计文件。

### 3.3 命令

```bash
uv run main.py evaluate-factor-marginal-contributions \
  --backtest-config config/backtest/multi_factor_quality_value_momentum.toml \
  --evaluation-start-date 2022-07-01 \
  --evaluation-end-date 2024-06-30
```

命令只支持 `multi-factor-quality-value-momentum`，评估日期必须成对出现。结果默认写入 `workspace/factor_marginal_contribution/<name>_<timestamp>/`。

### 3.4 输出

- `summary.md`：评估范围、共同候选池、权重协议、收益风险成本和解释边界；
- `parameters.json`：原始/实际配置、因子版本、正式权重、变体权重、共同候选池口径和基准状态；
- `marginal_contribution.csv`：15 个变体的收益、风险、换手、成本、目标覆盖和相对完整组合差异；
- `marginal_daily_nav.csv`：逐变体逐交易日净值和基准净值；
- `marginal_trades.csv`：逐变体逐笔成交、清算、跳过和成本；
- `marginal_targets.csv`：逐变体逐信号日目标权重；
- `marginal_coverage.csv`：共同候选池数量、目标数量和成功状态；
- `marginal_target_overlap.csv`：各变体与完整组合的逐信号日目标重合。

报告必须完整保留所有单因子和 leave-one-out 结果，不按收益排序后只保留最优方案。

## 4. 验收标准

- 纯逻辑测试覆盖 15 个变体生成、正式权重归一化、leave-one-out 权重、共同候选池、目标重合和不支持策略/日期参数错误。
- 集成路径验证所有变体共享同一 `PreparedMarketData` 和正式 `DailyBacktestEngine`，并验证重复行情输入、ASOF 连接顺序和集合遍历不会改变结果。
- 使用正式七因子配置在锁定测试区间运行 15 个变体，检查信号日、候选数、目标数、成本和交易记录完整。
- 通过 Ruff、全量测试和 Review Gate 后提交。

## 5. 解释边界

单因子收益高不等于该因子应获得更高正式权重；leave-one-out 变化也可能包含重新归一化、排名和组合交易路径变化。共同候选池减少了覆盖混淆，但不能消除样本外区间长度、因子相关性和多重比较带来的研究风险。

## 6. 真实运行结果与状态

已完成（提交 `28d4e4e`）。在锁定评估区间 `2022-07-01..2024-06-30` 使用正式七因子配置运行 15 个变体、24 个信号日，全部变体均为 24/0 成功/失败信号日。完整组合总收益 25.74%、年化收益 12.18%、年化波动 18.21%、夏普 0.75、最大回撤 -15.81%；基准 `510300` 在本区间没有行情，报告明确保留为不可用，不伪造基准结果。

实证过程中发现并修复了三类可复现性问题：存量 `daily_kline` 同日重复行、估值/指标 ASOF 右表未排序、回测调仓集合未排序。修复后独立运行两次，目标、净值、成交、覆盖和目标重合六份 CSV 完全一致。该结果仅用于边际贡献研究，不改变正式策略权重。
