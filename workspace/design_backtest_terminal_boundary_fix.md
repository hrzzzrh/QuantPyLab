# 回测区间尾部信号与退市清算修复设计

**日期**：2026-08-23
**状态**：实现、完整门禁、真实验证、Review Gate 与精准提交均已完成
**范围**：月末信号确认、退市清算确认、回测与研究评估回归

## 1. 问题与证据

测试期运行到 2026-08-23、实际行情截至 2026-08-21 时出现两个错误：

1. 2026-08-21 被当成 2026 年 8 月的月末信号日。根因是现有月末函数按月份直接取输入数据最大日期，没有确认下一个交易日是否已经进入下个月。
2. 2026-08-21 收盘后，当前 50 只持仓全部生成 `DELIST` 清算。根因是引擎先把行情截断到回测结束日，再把每只股票在截断区间内的最大日期当作真实最后交易日。

元数据核验显示，这 50 只股票全部为 `is_active=1` 且 `last_trade_date=NULL`，因此清算是回测区间尾部误判，不是真实退市。

## 2. 修复原则

### 2.1 月末信号

- 月末交易日必须由后续交易日确认：当前交易日之后存在下一交易日，且下一交易日已经进入新月份。
- 数据序列最后一个日期没有后续交易日证据，不生成月末信号。普通回测中该信号本来也无法完成 T+1 开盘成交。
- 月末判断只保留一个公共纯函数，行情财务物化、四个策略、训练器和研究诊断统一调用，禁止重复实现不同口径。
- 公共函数使用职责明确的名称 `get_confirmed_month_end_trading_dates`。

### 2.2 退市清算

- 禁止从已经按回测区间截断的行情推断真实退市日期。
- `BacktestDataAccess` 从 SQLite 元数据事实表 `stocks` 读取确认记录；只有 `is_active=0` 且 `last_trade_date` 为有效 `YYYYMMDD` 时才返回确认退市日期。
- 引擎只对确认退市日期与当前交易日一致的持仓生成 `DELIST`。
- 在市股票、退市日期缺失股票以及没有确认元数据的股票均不得生成 `DELIST`；行情缺失继续走现有不可成交/持仓冻结逻辑，不伪装成退市。
- `PreparedMarketData` 不再保存由截断行情计算出的 `last_trade_dates`，确认退市日期作为独立、显式输入传入引擎。

## 4. 兼容性与结果预期

- 已经具备下一交易日的历史月份信号不变。
- 回测区间最后一个未执行信号会从 `rebalance_targets.csv` 删除。
- 已确认退市股票仍在真实 `last_trade_date` 收盘后清算。
- 普通在市股票在回测末日继续保留持仓，不再变成全现金。
- 本次错误信号没有执行，错误清算按最后收盘价值且成本为零，因此预计收益净值不变；必须通过真实复跑验证，不能以设计预期代替结果。

## 5. 测试与验收

### 5.1 单元测试

1. 不完整月份的最后观测日不被认定为月末。
2. 下一交易日进入新月份时，前一交易日被认定为月末。
3. 数据尾部的在市股票不生成 `DELIST`，最终仍有持仓价值。
4. 显式确认退市日期的股票在该日收盘后清算。
5. 行情提前结束但没有确认退市元数据的股票不被误判为退市。
6. Runner 将数据访问层返回的确认退市日期完整传入普通和缓存回测路径。
7. 数据访问层只接受 `is_active=0` 且格式有效的 `last_trade_date`。
