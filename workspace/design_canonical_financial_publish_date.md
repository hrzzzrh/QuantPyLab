# 财务报告期统一公告日期口径设计提案

**提案日期**：2026-08-17
**提案状态**：已确认并实施
**适用范围**：三张新浪财务报表与东方财富财务指标表的同报告期日期统一

## 1. 背景与目标

当前 `FinancialStore.save_statement` 使用东方财富 `fin_indicator` 的公告日期覆盖新浪资产负债表、利润表和现金流量表的公告日期。000418 的实测数据表明，2015-09-30 的东方财富日期为 2016-10-25，但该报告期原始三季报公告日为 2015-10-27；2016-09-30 的原始报告公告日为 2016-10-25。

本次调整目标是恢复“报告期首次披露日”的统一口径，消除仅信任单一数据源造成的错误日期和同日 TTM 右表键重复。

## 2. 统一日期规则

对同一 `symbol`、同一 `report_date`，收集以下四个日期：

1. `fin_balance_sheet` 的 `公告日期`；
2. `fin_income_statement` 的 `公告日期`；
3. `fin_cashflow_statement` 的 `公告日期`；
4. `fin_indicator` 的 `公告日期`（东方财富 `NOTICE_DATE`）。

日期先统一为 `YYYYMMDD`，然后取所有非空日期的最小值：

```text
canonical_publish_date = min(non_null_publish_dates)
```

该字段被定义为“报告期首次披露日期口径”，不是“四类数据在同一时点全部可用日期”。四张表的 `公告日期` 均覆盖为该统一日期。

为防止最小日期被误当成全部数据的可用时间，另生成派生字段 `数据可用日期`：对四个来源的当前日期取最大值。该字段只作为 TTM 与 ASOF 的安全生效边界，不保存任何来源专属原始日期。

如果某个来源缺少该报告期或日期为空，则使用其余已存在的非空日期；四个来源全部缺失时不生成统一日期，也不覆盖已有非空值。

本次不保留四个来源的原始日期字段。代码注释必须明确：由于后续报告可能重新展示历史比较数据，单个来源的日期可能晚于首次披露日；统一取最早非空日期用于恢复首次披露口径，覆盖四张表后不再保留来源间日期差异。`数据可用日期` 是四源日期的最大值派生结果，不是原始字段副本。

## 3. 000418 验证口径

实现前后必须用固定样本验证：

| 报告期 | 资产负债表 | 利润表 | 现金流量表 | 东财指标 | 统一日期 |
| :--- | ---: | ---: | ---: | ---: | ---: |
| 2015-09-30 | 2015-10-27 | 2016-10-25 | 2016-10-25 | 2016-10-25 | 2015-10-27 |
| 2016-09-30 | 2016-10-25 | 2017-10-25 | 2017-10-25 | 2016-10-25 | 2016-10-25 |

重新计算 TTM 后，四表的 `公告日期` 应分别为 2015-10-27 和 2016-10-25；TTM 与 ASOF 使用 `数据可用日期`，不能因为最小公告日期覆盖而提前暴露尚未全部可用的数据。

## 4. 实现方案

### 4.1 新增共享日期归一化逻辑

新增一个存储层共享组件，负责：

- 按 `symbol` 读取四类数据的 `report_date` 与 `公告日期`；
- 标准化日期字符串并计算每个报告期的最小非空日期；
- 同时计算四源日期的最大值作为 `数据可用日期`，回写到三张报表和指标表；
- 将最小日期作为统一 `公告日期` 回写到三张报表和指标表；
- 对缺失来源、空日期和日期解析失败记录日志，不用异常值覆盖有效日期。

`FinancialStore` 和 `IndicatorStore` 在各自写入完成后调用该共享逻辑，避免同步顺序不同导致只有一部分表被归一化。现有“只从 `fin_indicator` 读取日期并强制覆盖”的逻辑删除。

### 4.2 同步顺序与已有数据

同步命令仍保持现有职责：

- `sync-financial` 抓取并写入三张新浪报表；
- `sync-indicators` 抓取并写入东方财富指标。

任一命令完成单股写入后都执行该股票的日期归一化。由于现有数据已经被旧逻辑覆盖，代码变更后必须重新抓取并写入 000418 的三张报表和指标表，再执行 `calc-ttm --symbol 000418`，不能只依赖旧 Parquet 中已覆盖的日期恢复原始口径。

### 4.3 ASOF 相关边界

最小日期规则用于恢复首次披露日期，不能直接作为 ASOF 生效日。TTM、指标 ASOF 和估值视图使用四源最大日期派生的 `数据可用日期`；同一 `symbol + pub_date` 的多条记录按 `report_date` 降序并以稳定记录哈希作并列键，明确选取最新报告期，避免重复 ASOF 匹配不稳定。
