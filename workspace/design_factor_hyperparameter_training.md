# 五个因子实验超参数的真实训练设计

**设计日期**：2026-08-20
**设计状态**：已完成
**适用范围**：`factor-composite-experiment` 的训练/验证/测试与 Walk-forward 评估

## 1. 背景与目标

当前训练器已经可以在训练窗口内拟合候选因子集合的非负 Ridge 因子权重，但候选配置中的结构参数和超参数仍由 TOML 固定。本次扩展在不改变点时数据、T+1 成交和测试集隔离规则的前提下，增加有限、可审计的参数组合搜索。

本次将训练的五个外层研究维度是：

1. **因子组合**：使用研究配置中显式列出的候选 TOML 代表不同因子集合和策略结构。因子组合不是把所有 14 个因子任意穷举，而是沿用候选白名单。
2. **因子窗口**：搜索候选因子声明的窗口参数，例如动量 `lookback_days` 或趋势 `trend_window`。
3. **持仓数量**：搜索 `holding_count`，决定每个月买入排名靠前的多少只股票。
4. **缩尾范围**：成对搜索 `winsorize_lower` 和 `winsorize_upper`，控制极端因子值压缩范围。
5. **Ridge 正则强度**：搜索 `ridge_alpha`，控制拟合权重的稳定程度和集中程度。

当前已经实现的因子权重拟合仍然保留：上述五项是外层超参数，因子权重是每个参数组合在训练窗口内重新拟合的内层模型参数。

## 2. 不纳入本次训练的参数

- `label_horizon_days`：它定义预测目标是未来几天收益，改变的是研究问题，不应和组合参数混在同一轮搜索中。
- `min_listing_days`：它改变股票池的上市阶段结构，先作为固定研究口径，避免把新股筛选和因子有效性混淆。
- `max_iterations`：只是优化算法的计算上限；如果已收敛，增加它不会改变策略。
- `minimum_training_observations`、`minimum_training_dates`：是数据质量门槛，不是收益优化参数。

以上参数仍可由 TOML 固定配置，训练器继续校验其合法性。

## 3. 配置协议

在现有研究配置中新增 `[hyperparameter_search]`：

```toml
[hyperparameter_search]
enabled = true
max_combinations = 100
holding_counts = [10, 20, 50]
winsorize_ranges = [[0.05, 0.95], [0.10, 0.90]]
ridge_alphas = [0.01, 0.1, 1.0]

[hyperparameter_search.factor_parameters.price_momentum_120d]
lookback_days = [60, 120, 240]

[hyperparameter_search.factor_parameters.price_reversal_20d]
lookback_days = [10, 20, 40]
```

具体规则：

- `candidate_configs` 仍是因子组合的唯一白名单；每个候选 TOML 作为一个因子组合候选参与搜索。
- `holding_counts`、`winsorize_ranges` 和 `ridge_alphas` 必须是非空、无重复、有限长度的数组。
- `factor_parameters.<factor_name>` 只允许声明该因子本身支持的参数；参数只应用于包含该因子的候选，未使用该因子的候选不会展开该维度，并在结果 `parameters.json` 的 `search_parameter_coverage` 中记录为 ignored。
- 候选未声明搜索网格的策略参数沿用候选 TOML 的固定值。
- 所有维度展开后的组合数量不得超过 `max_combinations`；超过时直接报错，防止误配置产生无法预估的全量回测。
- `[training]` 仍控制标签期限、Ridge 拟合迭代上限和训练样本门槛；`[hyperparameter_search]` 只控制外层候选组合。

关闭或省略 `[hyperparameter_search]` 时，保持当前行为：训练每个候选的因子权重，再用验证集选择候选。

## 4. 训练、选择与测试流程

每个固定切分或 Walk-forward 窗口按以下顺序执行：

1. 展开“候选因子组合 × 因子窗口 × 持仓数量 × 缩尾范围 × Ridge 强度”的有限组合。
2. 对每个组合，只使用训练区间内的点时数据计算因子，并用训练窗口的月末信号和未来收益拟合该组合自己的非负 Ridge 权重。
3. 使用该组合拟合出的冻结权重、窗口参数和结构参数运行训练集记录，随后在验证集运行同一组参数。
4. 只用验证集的选择指标在全部成功组合中选择一个组合。验证集是模型选择集，不能把它当作最终无偏绩效；最终无偏结果仍只看测试集。
5. 测试集只运行被选中的一组参数和对应训练权重。未入选组合不读取测试区间。
6. Walk-forward 每个窗口从头展开组合、重新训练和重新选择，不继承前一窗口的参数或权重。

若某个组合样本不足、因子窗口不合法、权重全部退化为零或回测无法生成有效验证指标，则记录失败原因并排除；所有组合失败时当前窗口终止。任何失败都不能回退到候选 TOML 的默认权重。

## 5. 五个参数的实际含义

| 搜索维度 | 训练时改变什么 | 对结果的影响 |
|:---|:---|:---|
| 因子组合 | 选择哪些因子共同进入模型 | 决定模型看到的信号来源；由候选 TOML 白名单控制 |
| 因子窗口 | 改变动量、反转或趋势计算回看长度 | 决定信号偏短期还是偏中长期，并改变所需历史数据 |
| `holding_count` | 改变每次实际买入的股票数量 | 少则组合集中、波动可能更大；多则分散但信号更稀释 |
| 缩尾范围 | 改变训练、验证和测试的极端值处理 | 防止少数异常值主导排名，同时会改变可用的截面差异 |
| `ridge_alpha` | 改变训练权重的正则惩罚 | 较大时权重更保守、较不容易集中在单一因子 |

因子权重不属于上表的外层网格，而是每一个组合在训练集内单独学习的结果；例如同一组因子在不同 Walk-forward 窗口可以得到不同权重。

## 6. 输出协议

在现有输出基础上新增或扩展：

| 文件 | 内容 |
|:---|:---|
| `hyperparameter_trials.csv` | 每个窗口、候选组合、五个搜索维度、训练状态、拟合权重、训练指标和验证指标 |
| `training_models.csv` | 每个成功组合的训练样本、迭代状态和最终拟合权重；失败组合记录原因 |
| `selections.csv` | 每个窗口被选中的候选 ID、五个外层参数、验证得分和测试结果 |
| `parameters.json` | 完整研究配置、展开数量限制和实际搜索空间快照 |
| `summary.md` | 入选参数、失败组合数量、验证选择结果和测试结果 |

`candidate_metrics.csv` 保留兼容输出；当搜索启用时，具体参数组合以 `hyperparameter_trials.csv` 为准。

## 7. 未来函数与统计边界

1. 因子窗口只使用信号日及之前的行情；训练标签所需的窗口后行情只用于训练标签。
2. 缩尾、排名、权重拟合和结构参数选择均严格按训练/验证/测试区间的时间顺序执行。
3. 验证集会参与外层参数选择，因此验证得分属于选择后指标；测试集仍保持完全隔离。
4. 本次不把 `label_horizon_days` 放入搜索，避免同时改变标签定义和策略参数导致结果不可解释。
5. 后续若需要更严格的超参数无偏估计，再增加训练集内部时间序列交叉验证或嵌套 Walk-forward，不在本次范围内隐式加入。

## 8. 验收标准

- 配置解析能拒绝非法参数、重复值、未注册因子参数和超过组合上限的搜索空间。
- 单元测试覆盖组合展开、候选参数覆盖、训练失败排除、验证选择和测试集只执行入选组合。
- 真实点时烟测至少覆盖两个候选因子组合和两个以上搜索维度，并在报告中出现实际非默认参数和拟合权重。
- 既有不启用超参数搜索的研究配置结果和 `run-backtest` 行为保持不变。
- Ruff、全量测试和真实烟测全部通过；设计已完成实施。
