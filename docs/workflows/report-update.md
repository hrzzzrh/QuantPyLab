# Report Update Workflow

本 workflow 用于更新 `investigation/` 下行业、专题或其他研究报告。

## 入口判断

当用户指定某个研报文件，并要求更新数据、更新研判、刷新跟踪框架或同步最新行业情况时，使用本 workflow。

## 完整阅读

更新前必须完整阅读目标研报，重点识别：

1. 报告原有日期。
2. 持续跟踪框架中的具体跟踪事项。
3. 当前基准值、触发条件和结构性修订条件。
4. 各章节中的关键数据表、核心判断和结论链条。

## 数据收集

按跟踪框架逐项搜集最新数据：

1. 优先使用官方或权威来源。
2. 补充上市公司公告、定期报告、行业协会、咨询机构和券商资料。
3. 标注数据实际统计截止时间。
4. 对关键数据至少尝试两个独立来源交叉验证。
5. 对尚未发布的新数据，如实说明最新数据仍未可得，不得编造或外推。

## 更新规则

1. 优先更新过时的数据表和当前基准值。
2. 仅当连续数据变化、结构性事件或触发条件成立时，才修订趋势研判。
3. 不添加更新日志、修订记录或与研报正文无关的过程说明。
4. 研报正文只体现当前有效判断。若新数据或新事件已经推翻旧结论，必须直接替换、重写或删除旧结论，严禁保留旧结论后再追加“已被覆盖”“已失效”“历史判断”等说明。
5. 历史复盘、事件流水、触发记录如有保留价值，应放在跟踪手册或工作区材料中，不放在结论型研报正文中。
6. 不为了本次更新压缩、删减或改写无关存量内容。

## 日期和文件名

更新 `investigation/` 下任何研报内容时，必须同时完成：

1. 将正文中的 `**日期**`、`**研究日期**` 或 `**报告日期**` 更新为当前日期。
2. 将文件名结尾日期同步为当前日期。

例如：

```text
某行业深度报告_2026年7月19日.md
某行业深度报告_2026年7月25日.md
```

## 输出摘要

完成后向用户说明：

1. 更新了哪些数据项。
2. 哪些数据仍无法获取及原因。
3. 是否修订研判结论。
4. 日期与文件名是否已同步。
