# Report Update Workflow

本 workflow 用于更新 `investigation/` 下行业、专题或其他研究报告。

## 入口判断

当用户指定某个研报文件，并要求更新数据、更新研判、刷新跟踪框架或同步最新行业情况时，使用本 workflow。

## 完整阅读

更新前必须完整阅读目标研报，重点识别：

1. 报告原有日期。
2. 持续跟踪框架中的具体跟踪事项。
3. 当前基准值、触发条件和结构性修订条件。
4. 各章节中的关键数据表、核心判断和结论链条。
5. 对核心判断有直接影响的关键公司、项目开发商或供应链公司。

## 数据收集

按跟踪框架逐项搜集最新数据：

1. 优先使用官方或权威来源。
2. 补充上市公司公告、定期报告、行业协会、咨询机构和券商资料。其中，公司定期报告、业绩公告、交易更新、交易所和监管公告均为一手来源；媒体报道仅作为线索或辅助证据。
3. **关键公司披露追踪**：对报告中影响核心结论的关键公司，检查其自原报告日期以来的官方 IR/公告页、财报日历和重大新闻，重点关注定期报告、业绩指引、订单、产能、项目 FID/交付及融资事项。已公开的定期报告不得因其经营统计期早于当前日期而遗漏。
4. 标注数据实际统计截止时间和公告发布时间；对有明确频率的指标更新至最新一期，对事件型指标搜索自原研报日期以来的新事件。
5. 对关键数据至少尝试两个独立来源交叉验证；若仅存在唯一一手来源，如实说明。
6. 对尚未发布的新数据，如实说明最新数据仍未可得，不得编造或外推。

## 更新规则

1. 优先更新过时的数据表和当前基准值。
2. 仅当连续数据变化、结构性事件或触发条件成立时，才修订趋势研判。
3. 关键公司新披露若改变产能利用率、订单、项目节奏、盈利指引、融资或竞争格局，必须同步复核摘要、相关数据表、时间线、情景分析和核心结论；不得只更新公司章节而保留矛盾结论。
4. 不添加更新日志、修订记录或与研报正文无关的过程说明。
5. 研报正文只体现当前有效判断。若新数据或新事件已经推翻旧结论，必须直接替换、重写或删除旧结论，严禁保留旧结论后再追加“已被覆盖”“已失效”“历史判断”等说明。
6. 历史复盘、事件流水、触发记录如有保留价值，应放在跟踪手册或工作区材料中，不放在结论型研报正文中。
7. 不为了本次更新压缩、删减或改写无关存量内容。
8. **防"追加式堆叠"（强制）**：
   - 更新采用"替换式"而非"追加式"：被新数据覆盖的过期观测（历史数据表、失效判断、陈旧时间线）当次删除或压缩为摘要，不得以"🆕"标注累积保留。
   - 研报与跟踪手册的小节编号必须连续无跳变、无重复标题；发现历史遗留编号错乱当次修复。
   - 章节标题不得堆叠"第X次修正/第X版"式更新日志标注，统一使用日期或直接删除；修正轨迹可保留一行，完整流水放入《研报更新说明》或跟踪手册。
   - 跟踪手册中已确认完成的验证点当次移入「归档记录」，前台只保留待验证项。

## 日期和文件名

更新 `investigation/` 下任何研报内容时，必须同时完成：

1. 将正文中的 `**日期**`、`**研究日期**` 或 `**报告日期**` 更新为当前日期。
2. 将文件名结尾日期同步为当前日期。

例如：

```text
某行业深度报告_2026年7月19日.md
某行业深度报告_2026年7月25日.md
```

## 输出摘要

完成后向用户说明：

1. 更新了哪些数据项。
2. 已追踪的关键公司及其最新财报、公告或重大新闻。
3. 哪些数据仍无法获取及原因。
4. 是否修订研判结论。
5. 日期与文件名是否已同步。
