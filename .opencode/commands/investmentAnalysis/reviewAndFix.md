用户指定目标公司：$ARGUMENTS。执行以下全流程 SOP，将"审查 → 裁决 → 修正"一次性闭环。

## 阶段零：材料定位

1. 确认目标公司目录 `investigation/equities/<公司>/` 及其下 `reports/` 全部章节与跟踪手册存在，列出清单，并全量阅读研报章节与跟踪手册，为后续审查意见裁决做准备。
2. 阅读 `investigation/equities/deep_investment_analysis_framework.md`（框架基准）与 `.opencode/commands/investmentAnalysis/redoStandard.md`（标准研报流程基准）。
3. 从 `investigation/equities/note.md` 定位该公司的汇总行与跟踪审计日历行。
4. 若有疑问先规划步骤，禁止跳过材料直接审查。

## 阶段一：独立审查（委托 research-reviewer）

启动 `research-reviewer` 子代理执行独立审查。任务 prompt 必须包含：

- 被审材料：`investigation/equities/<公司>/` 下全部研报章节 + 跟踪手册（要求完整阅读，禁止选择性阅读），审查基准为框架文件。
- 审查维度：框架合规（SOTP、证据回溯制、三态概率、全变量对冲矩阵等强制项）、乐观偏差（利好夸大/利空低估）、逻辑缺陷、事实错误（算术复算、跨章节一致性）、内部不一致、**结构整洁度（"追加式堆叠"检查：重复或跳变的章节编号、被新数据覆盖却未清理的历史观测数据、带"🆕/第X次修正"标注的更新日志式标题、跟踪手册中已完成验证点未归档）**。
- 量化核实时允许子代理通过系统视图（`v_daily_valuation`、`daily_kline`、`fin_*`）实测，禁止全量扫描 `data/` 目录。
- 输出格式：结论总评 + 问题清单（编号/所属章节/问题类型/严重程度/描述/修改建议）+ 事实核查表。
- 子代理只输出审查意见，禁止修改任何文件（agent 已设 edit: deny）。

等待子代理返回完整审查报告后再进入下一阶段，不得在审查未完成时并行开展修正。

## 阶段二：审查意见裁决（数据实测 + 独立判断）

对子代理的每条意见逐条独立复核，**严禁未经核验直接采信**：

1. **数据/事实类主张**：通过系统视图实测复核（`v_daily_valuation` 行情与估值、`daily_kline` K线、`fin_income_statement`/`fin_balance_sheet`/`fin_cashflow_statement` 财报、`fin_indicator` 指标）。查询脚本必须写入 `workspace/research/<公司>/scripts/` 后以 `uv run` 执行（如需导入 db_manager 加 `PYTHONPATH=.`），禁止在命令行直接包裹 python 代码运行，禁止全量扫描 `data/`。
2. **算术类主张**：直接复算（EPS×股本=净利、加权目标价、基准市值、安全边际、概率加权、盈亏比、同比增速等）。
3. **逻辑/一致性类主张**：跨章节比对原文论证链条。
4. **外部数据类主张**（如行业规模、市占率、进口量）：本地视图无法核验的，按信源分级处理——有权威来源的采信并注明来源；无法核实到权威来源的，按数据可信度保守修正，并在汇报中注明其来源与核实状态（如"来源：XXX，未经权威来源交叉验证"）及处理依据。
5. **信源核验**：审查意见涉及事件类事实（订单、减持、处罚、政策等）时，优先以公司公告、交易所、巨潮资讯、公司官网、监管机构等可追溯来源核验；新闻稿和媒体报道只能作为辅助证据（线索），不得作为裁决依据；对关键数据至少尝试两个独立来源交叉验证。
6. **额外检查**：审查可能遗漏的算术错误与跨章节不一致，一并纳入修正清单（本轮实操曾发现审查遗漏的敏感性表 EPS 影响错误）。

裁决结论分三档：**成立**（含部分成立，修正其成立部分）/ **不成立**（必须给出理由）/ **待议**（向用户说明）。

## 阶段三：执行修正

1. **手术式修改**：仅修改裁决成立的条目，保留其余存量内容完整性（禁止占位符、禁止用"已被覆盖/已失效"式表述；修改后的正文必须体现现状，不得写成修订记录）。
2. **结构整洁度修复（防"追加式堆叠"）**：审查裁决成立的结构问题必须一并修复——清理被新数据覆盖的过期历史观测数据（历史量价表、失效形态、陈旧资金流向），修复重复/跳变的章节编号，移除"第X次修正/🆕"式更新日志标题，跟踪手册已完成验证点移入「归档记录」。更新采用"替换式"而非"追加式"。
3. **连锁传导**：任何估值/盈利数字的修改必须检查下游联动——EPS → 三态目标价 → 加权综合目标价 → 基准市值 → 安全边际 → 概率加权目标价 → note.md 汇总行、跟踪手册、其他公司研报中的交叉引用（如横向对比表中引用了本公司的盈亏比）。
4. **盈亏比口径**：遵循框架模块六的**盈亏比口径规范**（现价<保守价时公式不适用、记"下行空间为负"/∞+；严禁以其他估值下限代入公式），不在此重复。
5. **note.md 同步维护**：评级、仓位建议、目标价、估值区间、盈利预测、逻辑证伪点发生实质变化时更新汇总行；表按盈亏比降序排列（∞+ 组在最前）；时间戳同步更新。跟踪审计日历行仅在触发事件或审计日变化时更新。
6. **跟踪手册**：目标价、验证阈值、证伪警报与修正后的研报保持一致。
7. **清理**：删除阶段二中创建的临时验证脚本（若其无复用价值），保持 `workspace/research/` 干净。

## 阶段四：汇报

向用户输出：

1. 审查意见裁决表：每条意见（编号/类型/严重度）→ 成立/不成立 → 理由（实测数据或复算过程）。
2. 实际修改清单：文件 + 关键数字前后变化。
3. 结论性判断：评级与目标价是否发生变化、核心投资结论是否受影响。
4. 明确说明哪些意见被否决及理由，以及哪些外部数据未能核实到权威来源及各自的来源与核实状态。
